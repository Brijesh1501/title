Manage phone rules

Two independent lists drive the Phone Number Formatter: which CSV column headers to scan, and which number shapes to recognize and how to format them. Both replace what used to be hardcoded in the Apps Script — add, edit or retire either one here, no redeploy required.

Headers to scan

Any uploaded CSV column whose header matches one of these (case- and spacing-insensitive — "Phone No1" and "Phone No 1" are treated the same) has its phone numbers reformatted. Column order doesn't matter, only the header text; everything besides case and whitespace must still match exactly.

Number patterns

Each row is a number shape the formatter recognizes and how to rewrite it — no regular expressions to write, just plain fields. Country code is the optional "+<code>" prefix to recognize (leave blank for a pattern with no country code). Digit groups is the national number's grouping as comma-separated sizes (e.g. "3,3,4" for an area code / exchange / line number, or "5,5" for a two-group 10-digit number) — numbers may appear in the source with any mix of spaces, dots or dashes between groups. Lower priority runs first when more than one pattern is active; put more specific patterns (a distinctive country code, a longer number) ahead of more general ones.
